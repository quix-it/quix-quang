# Quix Quang

Angular component and utility library developed by [Quix Srl](https://www.quixconsulting.com).

## Project Structure

This repository consists of two main parts:

1. **Quang Library** (`/projects/quang`): A comprehensive Angular library containing various components, services, and utilities for building Angular applications:
   - Authentication services and directives
   - UI components (autocomplete, checkboxes, date pickers, etc.)
   - Form utilities
   - Loading indicators
   - Overlay components (modals, popovers, toasts, tooltips)
   - Translation services
   - And more

   For detailed documentation on Quang components and modules, see the [Quang README](/projects/quang/README.md).

2. **Playground** (`/projects/playground`): A testing application for demonstrating and testing the Quang library components and features.

## Getting Started

### Prerequisites

The toolchain is pinned in [mise.toml](mise.toml): Node 24 and an exact pnpm. With
[mise](https://mise.jdx.dev) installed, the first time in the folder:

```bash
mise trust && mise install
```

`node` and `pnpm` then resolve to the pinned versions inside the project; the docs workflow reads
the same file.

### Installation

```bash
# Clone the repository
git clone https://github.com/quix-it/quix-quang.git
cd quix-quang

# Install dependencies (also installs the git hooks)
pnpm install
```

## Development

### Running the Playground

To start the playground application for testing and development:

```bash
pnpm start:playground
```

This will serve the playground application locally at `http://localhost:4400/`.

### Building the Quang Library

To build the Quang library:

```bash
pnpm build:quang
```

The built library will be available in the `dist/quang` directory.

## Deployment

### Publishing the Library

Several scripts are available for publishing the library:

```bash
# Publish a prerelease version
pnpm publish:prerelease

# Publish a patch version
pnpm publish:patch

# Publish a minor version update
pnpm publish:minor

# Publish a major version update
pnpm publish:major
```

### Deploying the Playground

To deploy the playground application:

```bash
pnpm deploy:git
```

This will deploy the playground to GitHub Pages with the base href `/quix-quang/`.

### Docs previews for pre-release tags

This repo also supports publishing "preview" docs for pre-release tags (e.g. `20.6.1-0`, `20.6.1-beta.2`).

- Stable docs: https://quix-it.github.io/quix-quang/
- Pre-release preview docs (always overwritten): https://quix-it.github.io/quix-quang/preview/

Previews are generated by the GitHub Actions workflow in [.github/workflows/docs-gh-pages-preview.yml](.github/workflows/docs-gh-pages-preview.yml) whenever a tag matching `*.*.*-*` (or `v*.*.*-*`) is pushed.

## Development Workflow

### Commits

husky runs two hooks, installed by `pnpm install`:

- `pre-commit`: lint-staged, that is ESLint with `--fix` and Prettier on the staged files;
- `commit-msg`: commitlint with the conventional commits rules.

### Architecture checks

- ESLint rules at `error` have no backlog; the ones at `warn` still have violations to fix.
- [architecture.spec.ts](projects/quang/architecture.spec.ts) runs with the unit tests: relative
  imports stay inside their entrypoint, `quang/...` imports target an entrypoint root, no cycles
  between entrypoints or new ones between files, every imported package is declared in the library's
  `package.json`.
- [.claude/settings.json](.claude/settings.json) runs ESLint on every file Claude edits and, at the
  end of its turn, typechecks library and playground and runs the architecture spec.

### Linting and Formatting

```bash
# Run linting
pnpm lint

# Fix linting issues
pnpm lint:fix

# Format code
pnpm format

# Lint and format in one command
pnpm lint-and-format
```

## Version Management

The project uses `npm version` (npm ships with Node; publishing also stays on `npm publish` from
`dist/quang`) with automatic synchronization between the root package.json and the library's package.json:

```bash
# The sync-version script is automatically run during versioning
npm version [patch|minor|major]
```
